# Strava en Zancada

Implementado sobre el mismo sitio, sin sustituir perfiles, carreras manuales ni planes. El inicio de sesión sigue siendo individual con ChatGPT; la identidad procede del servidor de Sites. No se usan cuentas compartidas. Cada consulta de datos personales incluye el ID del usuario autenticado; el ID del atleta es único entre conexiones. Tokens AES-256-GCM con IV aleatorio y el ID de usuario como dato autenticado, almacenados solo en D1. Las tablas de Strava son nuevas; la migración no modifica runner_state.

## Restricción vigente (revisión: 01/10/2026)

Revisadas la [política de la API](https://www.strava.com/legal/api_policy) y el [acuerdo de la API](https://www.strava.com/legal/api), ambos en vigor desde el 1 de junio de 2026:

- 2.3 y 6.1: los datos de un atleta solo se pueden mostrar a ese atleta. **Permitido y implementado**: Zancada muestra a cada persona sus propias carreras.
- 5.4: prohíbe procesar los datos de Strava para «analytics, analyses, customer insight generation», también de forma agregada, y combinarlos con otros datos. No hay excepción para análisis mostrados al propio atleta. **No implementado**: volumen semanal, tiradas largas, marcas, sesiones comparables y adaptación del plan se calculan solo con los registros que la persona introduce en Zancada.
- 5.3: prohíbe usar datos de Strava, o datos derivados, con cualquier aplicación de IA, incluida su inclusión en el contexto de un modelo. **No implementado**: el plugin de ChatGPT y la consulta manual excluyen Strava. La única excepción es el MCP oficial de Strava para uso personal (3.5), que no es una vía para aplicaciones de terceros.
- 5.5 y 6.2: caché de siete días como máximo y ningún almacenamiento persistente ni exportación. **Implementado**: purga a los siete días, sin exportación y sin copiar datos de Strava en el registro manual.
- 3.2: para superar límites publicados hay que contactar con developers@strava.com. Solo una autorización escrita de Strava permitiría los usos de 5.3 y 5.4. Ni una variable de entorno ni el consentimiento del atleta bastan, así que no existe ningún interruptor para activarlos.

Marca: el botón de conexión es el recurso oficial «Connect with Strava» (`public/strava/connect-with-strava.svg`), el enlace a cada actividad dice «View on Strava» y la lista de actividades lleva el logotipo «Powered by Strava». Se indica que Zancada es independiente y no está desarrollada ni patrocinada por Strava.

La conexión es solo OAuth. Se ha retirado la ruta para pegar un access token manual, para que nadie pueda vincular una cuenta con el token de otra persona. `StravaService.ownToken` se conserva únicamente como utilidad de pruebas en el servidor.

El periodo consultado (90 días por defecto, 30/90/180/365 disponibles) no es el periodo de retención. Cada respuesta se conserva como máximo siete días; purga antes de lectura y trabajo periódico. Las notas escritas por el usuario se guardan aparte y sobreviven sin métricas, fecha, identificador ni enlace externo si se elimina o caduca la actividad. Desconectar elimina caché, tokens y trabajos inmediatamente. Borrar todos los datos elimina también notas y ajustes; confirma el borrado en la aplicación.

## Configuración externa pendiente

1. El propietario debe [registrar la aplicación](https://www.strava.com/settings/api), cumplir condiciones y aportar una política de privacidad con responsable y contacto reales. La guía vigente requiere suscripción de Strava para crear una app. Las nuevas aplicaciones empiezan en modo para un único atleta. Solicitar el acceso para 10 atletas desde el panel API; para superar esa capacidad, revisión y aprobación de Strava. Revisar siempre la capacidad y cuotas asignadas allí; no se implementa un sistema de tokens compartidos para evitarlas.
2. Configurar en el servidor de Sites `STRAVA_CLIENT_ID` y `STRAVA_CLIENT_SECRET` (secreto). Ya se han generado en el servidor `STRAVA_TOKEN_KEY` (32 bytes en Base64), `STRAVA_WEBHOOK_PATH_SECRET`, `STRAVA_WEBHOOK_VERIFY_TOKEN` y `STRAVA_JOB_SECRET`; no rotar la clave sin migrar/reautorizar las conexiones cifradas.
3. Authorization Callback Domain: el dominio de tu despliegue (en el original, `zancada-running.cramirezgar.chatgpt.site`). Callback OAuth completo en `STRAVA_REDIRECT_URI`: `https://<tu-dominio>/api/strava/callback`.
4. El sitio sigue privado. Para admitir amigos, invitarlos como visitantes del sitio, con sus correos y cuentas individuales. No hacerlos editores ni facilitar credenciales administrativas. No se ha modificado la audiencia ni enviado invitaciones sin destinatarios.
5. Strava no puede autenticarse contra la entrada privada de Sites. Preparado `strava-relay.mjs`: desplegarlo como entrada HTTPS pública separada, o equivalente de infraestructura. No se ha desplegado ese servidor. Variables secretas del relay: `SITES_SERVICE_TOKEN` (credencial de servicio del mismo sitio), `STRAVA_WEBHOOK_PATH_SECRET`, `STRAVA_WEBHOOK_VERIFY_TOKEN`, `STRAVA_JOB_SECRET`. Variable normal: `ZANCADA_ORIGIN=https://zancada-running.cramirezgar.chatgpt.site`. Jamás entregar la credencial de Sites a Strava ni al navegador. El relay solo reenvía el webhook del sitio; el tick se inicia desde su servidor.
6. Configurar un cron del relay cada cinco minutos (`*/5 * * * *`), para cola/reintentos, reconciliación diaria y purga. Alternativa: un programador servidor que invoque `POST /api/strava/tick` con la credencial de acceso privado `OAI-Sites-Authorization` y `Authorization: Bearer <STRAVA_JOB_SECRET>`. También hay handler `scheduled` en el Worker del sitio si la plataforma habilita cron; Sites no ha expuesto una configuración de cron aquí. Las peticiones tick no devuelven actividades.
7. Registrar una única suscripción global de Strava con `POST https://www.strava.com/api/v3/push_subscriptions`, formulario `client_id`, `client_secret`, `callback_url=https://<relay>/events/<STRAVA_WEBHOOK_PATH_SECRET>`, `verify_token=<STRAVA_WEBHOOK_VERIFY_TOKEN>`. Guardar el ID devuelto en `STRAVA_WEBHOOK_SUBSCRIPTION_ID` en Sites. La validación GET devuelve hub.challenge y verifica hub.verify_token. Eventos POST verifican ruta secreta, subscription_id, atleta conocido, tipos y antigüedad. Strava no ofrece firma HMAC del evento; un delete no borra directamente: se confirma con API autenticada y 404. Revocación se confirma con 401 del atleta.
8. Comprobar el cron y el webhook real antes de establecer `STRAVA_RETENTION_JOB_ENABLED=true`. La conexión/importación permanece deshabilitada mientras no se configure este requisito. La purga no debe depender del navegador. Tras modificar variables, publicar de nuevo para aplicarlas.
9. Ejecutar con cuentas reales autorizadas: OAuth, importación, webhook create/update/delete, revocación y reconexión. No se ha hecho: faltan aplicación, credenciales, relay, cron y atletas autorizados. Ningún estado de conexión/sincronización real se da por comprobado en esta entrega.

## Endpoints y límites

- `GET /api/strava/status`: solo usuario autenticado; readiness, `checklist` con el estado real de cada variable del servidor (sin sus valores), cuenta, estados, actividades de caché y notas. Ningún token en respuestas. La interfaz y el asistente de primer acceso muestran esta lista tal cual.
- `POST /api/strava/connect`: crea state aleatorio, hash de state y de cookie HttpOnly/Secure/SameSite=Lax, caduca en 15 minutos. Callback verifica usuario, cookie, state, consumo único y permisos de lectura. Sin configuración devuelve `configuration_pending`; nunca simula una conexión.
- `POST /api/strava/sync` y `/process`: lista paginada, detalles en cola persistente, sincronización incremental y reconciliación de caché. Solo Run, TrailRun y VirtualRun; cinta mediante trainer o VirtualRun. El ritmo no clasifica calidad.
- `POST /api/strava/notes`, `/delete-notes`, `/disconnect`: autorización de usuario y origen exacto. Desconexión detiene las escrituras en curso usando la versión de conexión; revocación remota recomendada con OAuth /revoke, fallback /deauthorize para token propio. Si falla, se informa para revocar manualmente.
- `GET/POST /api/strava/webhook/<secreto>`: reservado al relay; respuesta rápida y procesamiento posterior con waitUntil. `/tick`: autenticación servidor adicional.

Cuota compartida conservadora: 90 peticiones de lectura por 15 minutos y 900 por día, por debajo de las cuotas por defecto publicadas. Se leen headers globales y de lectura, Retry-After y 429; se bloquea hasta el siguiente periodo. Cola con lease, deduplicación, ocho intentos y espera exponencial limitada a una hora; manual permite reintentar fallos. Cada ejecución es acotada; el cron continúa aunque se cierre la web. No se repiten llamadas por pulsar repetidamente sincronizar mientras una lista sigue pendiente.

Referencias: [OAuth](https://developers.strava.com/docs/authentication/), [webhooks](https://developers.strava.com/docs/webhooks/), [cuotas](https://developers.strava.com/docs/rate-limits/), [inicio y capacidad](https://developers.strava.com/docs/getting-started/), [API](https://developers.strava.com/docs/reference/). Las cuotas del panel concreto prevalecen sobre cifras de las guías.
